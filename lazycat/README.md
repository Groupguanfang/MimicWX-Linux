# 懒猫微服

目标平台为 x86_64、lzcos 1.6.0 及以上；本次验证使用 lzcos 1.6.3 和 lzc-cli 2.0.8。
应用运行官方 Linux 微信 4.1.13.26 和 MimicWX OneBot 11。

## 构建

从微信官方 Linux 下载入口取得 `WeChatLinux_x86_64.deb`，保存为
`lazycat/downloads/wechat-4.1.13.26-amd64.deb`。
本项目不将微信安装包提交到 Git。Dockerfile 会校验固定版本和 SHA-256：

```text
a0db8caeee8d1e6cfe0aa5ce58710270f8d74a90ff4920f53a3fc22aa0956fe9
```

若官方已替换下载包，不能仅修改散列继续构建；须重新核对版本及密钥提取函数特征。
已有环境可以提供对应版本的官方安装包。

```sh
cd lazycat
lzc-cli project build
lzc-cli lpk lint ./cc.naily.mimicwx-v0.5.30.lpk
lzc-cli app install ./cc.naily.mimicwx-v0.5.30.lpk
```

Mac 使用 OrbStack 时，可为构建命令设置
`DOCKER_CONTEXT=orbstack BUILDX_BUILDER=orbstack`。
构建阶段执行 Rust release 测试；只清理 MimicWX 自身编译产物，保留依赖缓存，
防止长时间构建后 Cargo 因源文件时间戳较旧而错误复用旧二进制。

## 登录和连接

从应用的微信桌面入口扫码。登录后服务等待密钥和数据库就绪，再启用 OneBot。
OneBot 入口为 `wss://mimicwx.<微服域名>/api/onebot/ws`。
Token 保存在应用数据目录的 `state/api-token` 中；升级不会重新生成已有 Token。
连接参数及 Koishi 插件构建见 [ONEBOT.md](../ONEBOT.md)。

0.5.7 增加表情 AES-CBC 解密、媒体来源回退及限额缓存。在持久配置的 `[onebot]`
中设置 `media_url = "https://mimicwx.<微服域名>/api/onebot/ws"` 后启用。
下载复用已有的公开 OneBot 入口，每个文件使用独立随机标识；WebSocket 仍验证 Token。
当时尚不支持原生收藏表情发送；出站原生表情在 0.5.29 增加。
没有本地副本的非 HTTP CDN 标识仍不支持。
0.5.8 等待微信补齐刚发出的媒体消息内容，并补充只有 MD5 的收藏表情：下载时只读查询微信 `emoticon.db` 中已保存的
媒体地址与密钥，再使用同一下载解密流程，不需要重新收藏或上传表情。
消息主库或 WAL 内容更新、WAL/SHM 文件被微信轮换后会刷新读取连接，保留消息游标，
避免缓存和旧文件句柄导致收不到后续消息。
数据库以 `SQLITE_OPEN_READ_ONLY` 打开，仍可读取已有 WAL 中的新消息；
关闭连接时禁用自动 checkpoint，由微信管理自身数据库的写回和 WAL 生命周期。
SQLite 读取 WAL 时仍可能更新共享索引，不能把只读数据库连接解释为完全不接触 `-shm`。
0.5.11 将 OneBot 发送的数据库确认移到后台，保持文字和图片提交顺序，
查询和心跳不再被慢发送阻塞。`confirmation_pending` 与 `verified` 区分提交和确认；
REST 发送接口仍等待实际数据库回执。
0.5.12 增加普通图片和引用图片的本地读取：按当前会话、服务端消息 ID 与
`packed_info_data` 定位缓存文件，验证账号级 V2 图片密钥并解密，使用镜像内
ffmpeg 将 WXGF/HEVC 转为 PNG。原图不可用时返回带标记的缩略图。
无需重启微信或修改 ChatLuna 配置；本地未下载的图片仍需客户端完成下载。
0.5.13 修复出站文本引用泄漏 CQ 码和媒体地址：按消息段生成预览，
嵌套引用保留正文，@ 显示昵称，图片等媒体显示为类型占位。
出站引用仍是文本兼容显示，不产生微信原生引用卡片。
0.5.16 增加微信原生文字引用，发送前唯一匹配完整原消息并核对原作者；
无法匹配时返回错误，不回退为文本模拟引用。
0.5.17 分开传递实际昵称和个人备注，群聊的 `sender.card` 不再混入备注。
Koishi 与 ChatLuna Character 对新消息使用实际昵称，个人备注保留在
OneBot 的 `remark` / `display_name` 字段中；原生引用仍按微信界面的显示名定位。
0.5.18 将公众号文章和链接分享卡片转换为 OneBot `share` 段，同时保留
标题、摘要和 URL 的可读文本，兼容不处理 `share` 的 ChatLuna 消息转换。
原生引用、小程序、文件、音乐和转发卡片不受影响。
0.5.19 修复微信处于单会话页面时无法切换群聊的问题：搜索框被隐藏时，
先通过可见的“返回”或“微信”导航按钮恢复会话列表，再精确定位目标。
可见性按 AT-SPI 标准的 `showing` / `visible` 状态判断，隐藏的会话项
不会因 `resizable` 状态被误选；切换后仍核对目标输入框。
0.5.20 增加 OneBot `record` 入站及 SILK 媒体读取，并包含原生语音发送所需的
PulseAudio、ffmpeg 和虚拟录音源启动配置。语音识别由 Koishi 的 `voice-asr`
插件完成。数据库连接改为真正只读，并验证可读取尚未 checkpoint 的 WAL。
这些变更降低读取连接的写入权限；微信的 SIGBUS 崩溃仍需独立观察验证。
0.5.21 在微信删除统计文件、无法从统计文件找到 V2 图片密钥时，增加按当前
账号校验的密钥恢复和缓存，修复已下载的公众号段落转发图片被误报为未下载。
本地文件尚未写完时最多等待约 2 秒；真正的解密错误不会再被缺失的缩略图覆盖。
0.5.22 不再因为 WAL 文件增长而关闭并重开消息数据库连接：只读连接本身可以
持续读取新增 WAL 帧，频繁重开反而会反复触碰微信正在映射的 `-shm`。仅在
主数据库内容变化或数据库/WAL/SHM 文件被轮换时重建连接。启动脚本同时增加
微信进程监督，微信 GUI 异常退出后会自动重启，不再让容器保持假在线状态。
0.5.23 默认对不超过 40 个 Unicode 字符的单行消息逐字输入，按消息长度和
输入进度加快速度，加入小幅间隔变化及标点停顿。更长的消息、链接和含换行、
控制字符的消息整段粘贴，防止中途误触发送。中文及表情使用临时空闲 X11 键码，
输入结束或返回错误时恢复原映射；空闲键码不足时在开始输入前改为粘贴。
主窗口和独立聊天窗口都先核对空草稿，输入完整且焦点正确后才按 Enter。

可在持久配置 `/home/wechat/mimicwx-linux/config.toml` 中调整：

```toml
[typing]
enabled = true
max_chars = 40
```

`max_chars` 按字符计数，限制在 1～200；`enabled = false` 恢复全部粘贴。
修改后只需向 MimicWX 接口进程发送 SIGHUP。
ChatLuna Character 0.0.235 的发送前等待由工作区 TypeScript 工具
`work/local-plugins/scripts/character-transport-typing.ts` 调整：
运行 `npm run build:typing` 后，将生成的 `lib/character-transport-typing.cjs`
复制到 Koishi，执行
`node character-transport-typing.cjs --apply-character-typing /koishi/node_modules/koishi-plugin-chatluna-character`。
它保留原文件备份，同时修改 CJS/ESM 构建，仅对 MimicWXBot 跳过原来的文字、
表情及语音等待；其他适配器的策略保持原样。执行后重启 Koishi 应用。
Character 更新后需要重新检查并运行该工具；不支持的实现会在写入前报错。

0.5.24 将切换会话、单击、双击、右键及滚动前的鼠标定位统一改为平滑移动。
轨迹从 X11 实际指针位置出发，以轻微弯曲的路径逐渐加速再减速，终点精确落在
目标坐标。常规移动约 64～420 毫秒，距离越远通常耗时越长；4 像素以内最多
32 毫秒，已在目标时不增加等待。中间位置逐帧提交，按绝对时间安排，避免逐帧
通信时间叠加。屏幕外的目标及鼠标按键仍被按下时返回错误，避免误点或意外拖动。
无需新增配置，更新接口后默认启用。
0.5.25 在进入搜索回退时，先平滑移到搜索框并点击，再核对搜索框焦点，
避免直接设置焦点导致搜索框前缺少鼠标移动过程。
0.5.26 将数据库通知改为 inotify，只监听消息目录，不为事件打开数据库或共享
索引文件。原 fanotify 事件携带的文件描述符在关闭时会清除本进程在同一文件上
持有的 POSIX 锁；只读连接也不能避免这种问题。隔离复现确认原监听器会丢失锁，
新监听器保持锁。目录或 WAL 轮换后仍能恢复监听，事件队列溢出时重新查询消息。
这项修复消除已确认的锁干扰；微信 WCDB 线程的间歇性 SIGBUS 仍需继续观察，
不能仅凭短期在线认定全部崩溃原因已经消除。

0.5.27 将数据库读取改为独立只读快照。桥接不再打开微信的 contact/session/message
数据库，也不映射或写入微信的 `-shm` 共享索引。每次刷新先把主库和 WAL 复制到
`/tmp/mimicwx-db-snapshots-*` 的私有目录，再以只读连接查询；主库未变化时仅更新
WAL，两个槽位交替使用，避免修改正在读取的文件。WAL 可能在大小不变时重用旧帧，
因此版本变化时完整复制，不能只复制增长部分；复制期间再次变化时重试。
消息连接同时跟踪主库和 WAL 的版本，避免仅追加 WAL 时继续读取旧快照。
测试确认查询连接指向私有快照，
读操作不改变微信 `-shm` 的字节。代价是每条新消息刷新快照并重新派生 SQLCipher
密钥，约增加一百多毫秒；同一批 WAL 事件会合并刷新。该版本用于验证微信 WCDB
线程的 SIGBUS 是否由桥接长期持有共享索引导致，仍需持续观察，不能仅凭短期在线
认定所有崩溃原因已经消除。

0.5.28 修复短消息中不同字符数超过空闲 X11 键码数时，意外退回整段粘贴的问题。
每条消息仍独立使用相同的长度、链接及换行判定；符合逐字输入条件时，
按可用键码分批输入并恢复映射，再复用键码继续当前消息。加速进度按整条消息计算，
不因换批重置。主窗口、独立窗口及 OneBot 消息中的各段文字均使用此策略。
只有开始输入时完全没有安全可用键码，才退回整段粘贴；输入中途资源变化则保留草稿
并停止发送，避免重复输入或截断发送。完成日志中的 `batches` 记录本条消息使用的批次数。

0.5.29 将带 `sticker` 标记的 OneBot 图片发送为微信原生表情。
GIF 以 `text/uri-list` 文件地址粘贴，微信将其发送为类型 47 的动画表情；
普通图片仍使用图片剪贴板。静态图片先转换为不超过 512×512 的 GIF，
已有 GIF 保留动画，限制为 1 MiB、宽高各不超过 1000 像素。
临时文件保留至后台确认完成，避免微信异步读取 GIF 时文件已被删除。
客户端初始表情记录可能暂时保存空 MD5，监听等待内容补齐再核对
目标会话、自发消息、时间窗、类型 47 和文件 MD5。
不会把普通图片回执误认成表情。Koishi 适配器保留 `sticker: true` 标记，
群聊和私聊复用同一条发送链路。

0.5.30 在发送前清理目标会话输入框中残留的引用，并在提交时复核引用状态。
引用失败时通过删除按钮清理引用，会话搜索失败时直接清空搜索框，避免 `Esc` 触发 Linux 微信的退出登录确认框。
OneBot 发送失败日志会记录微信桌面锁定、退出登录确认和引用目标无法定位等具体原因。

接口热替换与容器内临时安装依赖不会改变已安装的 LPK。应用重建会重新加载已安装镜像，
因此正式升级应安装包含相同修复的完整包；升级将重新启动微信，可能需要手机确认登录。

桌面及 REST API 使用懒猫身份认证；只有 `/api/onebot/ws` 绕过平台登录，
该端点始终验证业务 Bearer Token。没有 Token 时不会开启 OneBot。
接口状态显示已登录不代表所有消息能力均已实现，请核对 OneBot 能力表和限制。

重启使用懒猫应用管理命令，对运行中的应用依次停止、启动：

```sh
lpk-manager stop cc.naily.mimicwx
lpk-manager start cc.naily.mimicwx
```

## 持久数据和权限

- `wechat`：账号设置。
- `wechat-files`：新版微信数据库和媒体。
- `config`：MimicWX 配置。
- `state`：Token、数据库密钥和密钥提取日志。
- `state/profile`：微信用户目录，包括 `.sys1og.conf`、用户设置及网页组件资料；原有数据库和账号目录继续使用各自的挂载。
- `state/machine-id`：本实例固定的 D-Bus 与系统设备标识，在启动 D-Bus、微信之前恢复。

从 0.5.0 升级前，在旧容器仍运行时执行 `lazycat/profile.sh --snapshot`，
把当前用户目录与设备标识保存到原有的持久 `state` 目录，再安装 0.5.1。
脚本不打印凭据，不复制数据库、媒体或运行中的 D-Bus 缓存；重复执行会保留已有设备标识。
首次使用新挂载前务必完成快照，避免容器替换丢失尚在临时层中的配置。

登录资料和设备标识持久化能避免容器重建引入新的本地环境，不能替代微信服务端的登录验证。
是否可自动登录仍取决于客户端设置及微信的验证结果。日常调整 Koishi 只重启 Koishi 应用，
无需重启微信桌面。
仅更新接口进程时，可向 MimicWX 进程发送 SIGHUP；监督脚本会重启接口，
保持微信桌面、X11 和当前登录不变。整个应用升级仍可能需要手机确认。

热替换接口二进制时，先校验构建产物的 SHA-256、备份旧文件，再安装到
`/usr/local/bin/mimicwx.next`。新文件必须重新设置
`setcap cap_sys_admin+ep /usr/local/bin/mimicwx.next`，然后原子重命名为
`/usr/local/bin/mimicwx` 并向原接口进程发送 SIGHUP。文件替换不会继承旧文件的
capability；旧版 fanotify 构建遗漏时无法启动文件监听，消息只能等待兜底轮询，
发送回执可能超时。0.5.26 的 inotify 监听不依赖 `SYS_ADMIN`。
完成后核对微信 PID、在线状态、文件 capability、WAL 监听和 Koishi 自动重连。
该方式更新当前容器；容器重建及应用升级仍以 LPK 内的二进制为准。

Token、密钥和配置权限为 `0600`，不应上传到代码仓库或工单。
桌面和 MimicWX 以独立 `wechat` 用户运行；初始化过程以 root 设置文件权限、
附加 GDB。应用使用 `runc`，通过 `compose.override` 申请 `SYS_ADMIN` 和 `SYS_PTRACE`，
分别兼容旧版 fanotify 构建和本实例的密钥提取，不修改宿主机系统配置。
